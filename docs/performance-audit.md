# 1.13.1 性能实测与证据边界

这份报告提供可复现的当前版本基准，不能据此宣称所有设备都“低占用”或已经完成性能优化。

## 测试条件

- 2026-09-28（Australia/Sydney），Windows 11，Ryzen 9 9950X3D，32 逻辑处理器，系统可用物理内存约 61.6 GiB；本机安装 RTX 5080 和 AMD 集显。
- 应用源码版本 1.13.1，提交 `a235d2957444a176d84ec41fd360c7d71849bdbf`，Electron 44.4.5。用与发布版相同的源码渲染，通过独立测试存档运行；不是对已安装发行包的测量。
- 桌面 1920×1080、60 Hz、100% 缩放；角色尺寸 320，每位学生的模型画布为 832×832。
- 1 / 3 / 6 位学生待机，以及 6 位暂停、隐藏；每种场景预热后连续采 3 轮，每轮约 20 秒。场景按这个顺序在同一进程实例运行，重复轮次不是独立冷启动。
- 学生 ID：212、426、218、327、208、209。开启模型物理与特效开关；关闭语音、主动邀约、自主行走和窗口行走；没有摆放家具、没有主动触发粒子。因而不能代表激烈交互或满家具的峰值。
- 程序使用正常图形后端、可见透明窗口；没有降为软件测试材质，没有打开计算额外模型包围盒的 `--measure-pet`。调试连接和轻量绘制统计仍有测试开销。
- 基准结束后单独启动相同配置探测，WebGL 上下文为 RTX 5080 / ANGLE D3D11，硬件合成与 WebGL 已开启，见 [上下文记录](performance/1.13.1-gpu-context.json)。这项补充检查不等于测到了 GPU 利用率或显存。

## 指标口径

CPU 取 `app.getAppMetrics()` 中 Electron 管理的主进程、渲染进程、GPU 进程和工具进程的累计 CPU 秒差值。100% 表示占满一个逻辑核心；再除以 32 得到本机整机归一化比例。它不包括测试驱动和原生窗口扫描辅助程序，不能称为完整系统开销。GPU 进程的 CPU 时间也不是 GPU 利用率。[Electron CPUUsage 定义](https://www.electronjs.org/docs/latest/api/structures/cpu-usage)。

内存同时保留工作集和 Windows 私有内存。工作集相加会重复统计共享页，不等于去重后的实际物理内存；私有内存也不等于显存。没有将 JavaScript 堆大小冒充整个程序的内存。[Electron MemoryInfo 定义](https://www.electronjs.org/docs/latest/api/structures/memory-info)。

帧率统计实际包含 WebGL 绘制调用的不同 `requestAnimationFrame` 时间戳，同一帧多次描边/渲染只算一次。它表示渲染提交频率，不是显示器最终呈现帧率，也不是 GPU 执行时间。原始记录还包含帧间隔 P95、超过 50 ms 的间隔次数和非 rAF 绘制次数。

原始窗口记录中的 `hidden` 是 DOM 的 `document.hidden`，不是系统窗口可见状态；本应用关闭后台节流时，两者不能等同。隐藏场景通过应用的隐藏命令进入，绘制计数单独统计。复现脚本还会记录系统窗口可见状态；该附加字段和直接 WebGL 上下文记录是在本次长采样后加入的，因此原始 15 轮文件中不含这两项字段。

## 当前结果

| 场景 | CPU：单核心口径 | CPU：本机整机口径 | 工作集 MiB | 私有内存 MiB | 每窗口提交 FPS |
| --- | --- | --- | --- | --- | --- |
| 1 位待机 | 12.15–12.33% | 0.380–0.385% | 486–543 | 336–397 | 29.7–30.0 |
| 3 位待机 | 31.01–31.87% | 0.969–0.996% | 948–1006 | 728–791 | 29.5–30.0 |
| 6 位待机 | 61.16–66.97% | 1.911–2.093% | 1209–1340 | 1359–1494 | 28.7–29.8 |
| 6 位暂停 | 0.96–1.12% | 0.030–0.035% | 1257–1273 | 1355–1355 | 0.0–0.0 |
| 6 位隐藏 | 0.69–0.89% | 0.022–0.028% | 314–731 | 1359–1365 | 0.0–0.0 |

CPU 范围来自三轮各自的平均值；内存范围来自三轮各自的时间样本中位数；FPS 为所有轮次和角色的范围。完整采样见 [原始 JSON](performance/1.13.1-windows.json)。

六角色暂停后，测得的 Electron 进程 CPU 时间均值减少约 98.4%，隐藏后约 98.8%；这是状态切换的短时对照，不是版本升级的收益。暂停和隐藏采样中均无模型绘制调用。隐藏时工作集降低、私有内存仍保留约 1.3 GiB，不能据此声称已卸载资源。

待机提交帧间隔 P95 约 33.4–34.6 ms；个别样本存在超过 50 ms 的间隔，不应宣称完全没有卡顿。

## 已落实的优化机制

| 机制 | 可检查的实现 | 证据与限制 |
| --- | --- | --- |
| 桌宠动画限制到 30 FPS | [pet.js](../renderer/pet.js)、[model-viewer.js](../scripts/model-viewer.js) | 当前实测记录每个窗口的绘制提交频率；不是 60 FPS 档位。 |
| 暂停/隐藏停止动画循环 | [pet.js](../renderer/pet.js)、[desktop-scene.cjs](../electron/desktop-scene.cjs) | 由本次暂停/隐藏场景检验；停止绘制不代表释放所有内存或所有定时器。 |
| 粒子有数量上限，无粒子时不持续绘制 | [interaction-effects.js](../scripts/interaction-effects.js) | 40 粒子池、发射节流、粒子画布像素比上限 1.5；[交互测试](../tests/effects-desktop.cjs)检查粒子结束后帧计数不再增加。本次基准不测高频粒子峰值。 |
| 骨骼变换矩阵按姿态复用 | [pose-geometry.js](../scripts/pose-geometry.js) | 避免每个顶点重复组合同一骨骼矩阵。代码审查证明机制存在；不能单独给出当前版本节省百分比。 |
| 模型卸载时释放材质、纹理、动画和 WebGL 上下文 | [model-viewer.js](../scripts/model-viewer.js) | 释放路径存在；仍需要切换压力测试和长时间内存曲线，才能排查全部泄漏。 |
| 隐藏字幕不逐帧读取布局 | [pet.js](../renderer/pet.js) | 字幕尺寸由 ResizeObserver 缓存，降低无效布局工作。 |

现有旧测试 `tests/performance-desktop.cjs` 只测单角色约 6 秒的渲染线程任务耗时与 JS 堆。此前保存的 before/after 文件没有完整硬件、提交和重复采样记录，不用于证明当前 1.13.1 的总体改善幅度。

## 还不能承诺的部分

1. **多角色内存仍需优化。** 每位桌面学生建立独立窗口与渲染环境；不能把单角色结果套在 6 位学生上。应继续测重复资源、纹理与渲染环境的占用，评估共享资源和休眠卸载。
2. **缺少有代表性的设备覆盖。** 本次高端 Windows 机器不能代替核显笔记本、低配电脑、Intel Mac、Apple Silicon Mac，也没有电池续航/功耗数据。
3. **缺少长时间压力证据。** 尚未完成 2 小时挂机、100 次角色/家具切换、多学生拖拽与家具交互的内存和显存曲线；几分钟样本不能证明无泄漏。
4. **缺少严格的优化前后对照。** 后续每项优化应在同一硬件、同一资源、同一参数下，对两个明确提交交替重复测试，报告 CPU、内存、提交帧间隔及交互正确性，而不是只展示最好的一次。

## 复现

在依赖和所列学生资源已就绪的完整开发目录中：

```sh
node tests/performance-audit.cjs 20 3
```

也可以用第三个参数指定解包后的应用可执行文件，测试会从本地资源目录为独立存档准备所需学生：

```sh
node tests/performance-audit.cjs 20 3 "path/to/BA-Desktop-Pet.exe"
```

结果输出在 `test-results/performance-audit-<时间戳>/report.json`。测试使用单独配置，不修改用户日常桌宠存档；不会自动发布、下载更新或安装应用。
